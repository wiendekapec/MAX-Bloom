## 1. Что где живёт

Правило платформы: чат — для коротких действий и уведомлений, мини-апп — для форм, списков и дашбордов.

| Задача | Где |
|---|---|
| Выбор роли, главное меню, декларация самозанятости | Бот |
| Привязка канала (`bot_added`) и подтверждение | Бот |
| Все уведомления (оплата, напоминания, кик, ошибки) | Бот |
| Выдача прокси-ссылки на канал | Бот (сообщение) |
| Дашборд, тарифы, экспорт Excel | Мини-апп |
| Карточка сообщества, выбор тарифа, оплата | Мини-апп |
| Создание профиля и тарифа | Чат-опрос (Must) → форма в мини-аппе (Should, US-1.3) |

Мини-апп всегда открывается **из бота** (кнопкой или deep link), не как отдельный сервис.

## 2. Точки входа

| Вход | Поведение |
|---|---|
| `/start` без payload | Главное меню (п.3) |
| `/start business` | Сразу ветка продавца (п.4), минуя меню |
| `/start plan_{id}` | Мини-апп на карточке тарифа `id` (покупатель) |

Payload приходит в `message_created` → `payload.message.body.text` (`/start business`). **[СВЕРИТЬ]** нет ли отдельного события старта бота в актуальной доке.

## 3. Главное меню

Показывается всегда, независимо от прошлых действий (роль не блокирует ветки).

```
🌸 Добро пожаловать в MAX Bloom!
[💼 Кабинет продавца] [🛍 Каталог] [📋 Мои подписки]
```

| Кнопка | Действие |
|---|---|
| Кабинет продавца | Нет сообщества → онбординг (п.4). Есть → открыть мини-апп на дашборде |
| Каталог | Открыть мини-апп на списке (демо-заглушка) |
| Мои подписки | Показать подписки пользователя списком (п.6) |

При первом обращении: создать `users` (`max_user_id`, `first_name`, `role=USER`, `pdp_consent_given=true`).

## 4. Бот: поток продавца

Состояния диалога (FSM):

```
S0 ONBOARDING_INFO → S1 SELF_EMPLOYED_CONFIRM → S2 ASK_TITLE → S3 ASK_DESCRIPTION
→ S4 ASK_CATEGORY → S5 ASK_PLAN_TITLE → S6 ASK_PLAN_PRICE → S7 ASK_PLAN_PERIOD
→ S8 WAIT_BOT_ADDED → S9 DONE
```

| Шаг | Сообщение бота | Ожидаемый ввод | Валидация / действие |
|---|---|---|---|
| S0 | Инфо про самозанятость + ссылка npd.nalog.ru. Кнопки: `✅ Я оформлен`, `📖 Подробнее` | callback | — |
| S1 | «Подтверждаю, что зарегистрирован как самозанятый/ИП/ООО и отвечаю за легальность приёма платежей». Кнопка `Подтверждаю` | callback | `users.self_employed_confirmed=true`, `role=BUSINESS` |
| S2 | «Как называется проект?» | текст | 1–255 симв., иначе повторить вопрос |
| S3 | «Короткое описание (до 200 симв.)» | текст | ≤200, иначе повторить |
| S4 | «Выберите категорию» + 5 кнопок | callback | значение из списка категорий |
| S5 | «Название тарифа?» | текст | 1–128 симв. |
| S6 | «Цена в рублях?» | текст | число > 0, ≤ 6 знаков; иначе «Введите число, например 990» |
| S7 | «Период доступа» `7 / 30 / 90 дней / Разово` | callback | `period_days` = 7/30/90/0 |
| S8 | Инструкция: добавить бота админом с правом `add_remove_members`. Кнопка `⏳ Жду…` | событие `bot_added` | см. п.4.1 |
| S9 | «🎉 Тариф опубликован» + ссылка `https://max.ru/{BOT}?start=plan_{id}` + кнопки `📊 Дашборд`, `➕ Тариф` | — | `is_active=true` |

Тариф получает `is_active=true` **только после S1 и S8**.

**Хранение состояния диалога.** Схема БД под FSM ничего не предусматривает. Для MVP: in-memory карта `max_user_id → {state, черновик}` с TTL (сброс при рестарте — записать в «Известные ограничения» README). Альтернатива — таблица `bot_sessions(user_id, state, draft_json, updated_at)`.

**Прерывание:** любой `/start` или кнопка меню сбрасывает FSM. Текст вне ожидаемого шага — «Не понял. Продолжим?» + кнопки `Продолжить` / `В меню`.

### 4.1 Обработка `bot_added`

1. По `chat_id` найти черновик продавца (пользователь из события = автор черновика). Не нашли → игнорировать событие.
2. `GET /chats/{chatId}/members/me` — проверить право `add_remove_members`. Нет → сообщение «Дайте боту право управлять участниками, иначе кик неплательщиков не сработает», FSM остаётся в S8.
3. `GET /chats/{chatId}` → `Chat.link` в `communities.invite_link`.
4. Создать `communities` (`max_chat_id`), `subscription_plans` из черновика, перейти в S9.
5. Ошибка любого вызова → сообщение продавцу «Не получилось привязать канал», лог.

Формат события в контракте (`event_type`, `chat.id`) и в `MAX_API_notes.md` (`type`, `payload.chat_id`) **различается**. **[СВЕРИТЬ]** реальный вид.

## 5. Бот: поток покупателя

| Событие | Действие бота |
|---|---|
| `/start plan_{id}` | Кнопка открытия мини-аппа на карточке тарифа. Тариф неактивен → «Этот тариф больше не продаётся» |
| Оплата успешна (webhook) | Сообщение: «✅ Оплата прошла. Подписка до {дата}. Ваша ссылка: `{APP_BASE_URL}/i/{token}` (действует 24 часа)» + кнопка `Вступить →` |
| Оплата отменена | «❌ Оплата не прошла» + `🔄 Попробовать снова` (новый платёж, новый `idempotency_key`) / `💬 Поддержка` |
| Ошибка выдачи доступа | «Не получилось выдать доступ, поддержка уже уведомлена» + лог с `subscription_id` |

### Мои подписки (п.3)
Для каждой подписки: название, тариф, статус, `days_left`. Для `ACTIVE` кнопка `Прислать ссылку ещё раз` → новый `invite_tokens`, сообщение со ссылкой. Для `EXPIRED` кнопка `Продлить`.

## 6. Уведомления по расписанию

Шедулер (cron из `BLOOM_EXPIRATION_CHECK_CRON`, в контракте — раз в час):

| Условие | Сообщение | Дедупликация |
|---|---|---|
| `expires_at - now ≤ 3 дня`, `ACTIVE` | «⏰ Подписка на {название} заканчивается {дата}» + `🔄 Продлить за {цена} ₽` | не слать повторно (нужен флаг/дата отправки) |
| `expires_at` сегодня | «🔔 Сегодня истекает» + `Продлить` | так же |
| `expires_at < now` | кик + `status=EXPIRED` + «😔 Подписка завершена. Возобновить?» + `Подписаться снова` | — |

**Пробел в схеме:** шедулер запускается каждый час, поэтому без отметки «уведомление уже отправлено» пользователь получит его 24 раза. Добавить в `subscriptions` поля `notified_3d_at`, `notified_0d_at` (TIMESTAMPTZ, nullable).

Сверка участников канала (кик без подписки) — раз в сутки, отдельно от почасовой проверки сроков (см. `DIAGRAMS_v2.md`, п.2).

## 7. Callback-кнопки бота

Формат payload: `action:<имя>:<аргумент>` (как в `MAX_API_notes.md`).

| Payload | Действие |
|---|---|
| `action:role:seller` / `action:role:buyer` | Выбор ветки из меню |
| `action:selfemp:confirm` | S1 |
| `action:category:{key}` | S4 |
| `action:period:{days}` | S7 |
| `action:renew:{subscription_id}` | Новый платёж на тот же тариф |
| `action:resend_invite:{subscription_id}` | Новый токен и сообщение |
| `action:retry_payment:{plan_id}` | Новый платёж |
| `action:support` | Контакт поддержки |
| `action:menu` | Главное меню, сброс FSM |

После каждого callback ответить на `message_callback` (иначе у кнопки «крутится» индикатор). **[СВЕРИТЬ]** метод ответа на callback.

## 8. Мини-апп: карта экранов

Авторизация: заголовок `X-Init-Data` на каждом запросе, бэкенд проверяет HMAC-SHA256. Ошибка → `UNAUTHORIZED_INIT_DATA` → экран «Откройте приложение из бота».

Стартовый экран определяется параметром запуска: пусто → каталог; `plan_{id}` → карточка тарифа; запуск из «Кабинета» → дашборд. **[СВЕРИТЬ]** как MAX Bridge отдаёт start-параметр в мини-апп.

### Покупатель

| Экран | Данные | Действия |
|---|---|---|
| Каталог (демо) | `GET /api/v1/communities?category=` | тап по карточке → карточка |
| Карточка | `GET /api/v1/communities/{id}` | выбор тарифа → Чекаут |
| Чекаут | тариф из предыдущего шага | MainButton «Оплатить через СБП» → п.9 |
| Ожидание оплаты | `GET /api/v1/payments/{id}/status` (polling) | — |
| Успех | ссылка из ответа | «Вступить» → `/i/{token}` |
| Ошибка оплаты | `code` из problem+json | «Попробовать снова», «Поддержка» |

### Продавец

| Экран | Данные | Действия |
|---|---|---|
| Дашборд | `GET /api/v1/business/dashboard` | список тарифов, «+ Тариф», «Экспорт Excel» |
| Новый тариф | форма | `POST /api/v1/business/plans`, чекбокс декларации |
| Переключатель тарифа | — | `PATCH` активности (нового эндпоинта нет, см. п.11) |

### Состояния каждого экрана (критерий UX «сообщает о загрузке, результате и ошибке»)

| Состояние | Что показываем |
|---|---|
| loading | скелетон/спиннер, кнопки заблокированы |
| empty | текст + действие (напр. «Тарифов пока нет. Создать») |
| error | текст из `detail` ответа + `Повторить` |
| success | тост или экран результата + `HapticFeedback.notificationOccurred('success')` |

Error Boundary на корне приложения (НФТ-12).

## 9. Мини-апп: оплата пошагово

1. Тап MainButton → `HapticFeedback.impactOccurred('medium')`, кнопка блокируется.
2. `POST /api/v1/payments/create {plan_id}` → `payment_id`, `confirmation_url`.
3. Открыть `confirmation_url` (страница ЮKassa sandbox).
4. Возврат на `YUKASSA_RETURN_URL` → экран «Ожидание оплаты».
5. Polling `GET /payments/{payment_id}/status` каждые 2 с, максимум 60 с.
   - `SUCCEEDED` → экран успеха.
   - `CANCELED` → экран ошибки.
   - Таймаут → «Проверяем оплату. Ссылка придёт в чат с ботом» (webhook всё равно дойдёт).
6. Ошибки API маппятся по `code`: `PLAN_INACTIVE` → «Тариф больше не продаётся»; `PAYMENT_FAILED` → экран ошибки оплаты; `RATE_LIMIT_EXCEEDED` → «Слишком часто, подождите»; прочее → общий экран ошибки.

Повторный тап «Оплатить» не создаёт второй платёж, пока первый `PENDING`.

## 10. SDK мини-апп

| Возможность | Использование |
|---|---|
| `initData` | Заголовок `X-Init-Data` |
| MainButton | Единственная главная кнопка: «Продолжить» / «Оплатить через СБП» |
| HapticFeedback | Тап оплаты (`impact`), успех (`notification: success`), ошибка (`error`) |
| ThemeParams | Цвета из темы MAX через CSS-переменные, с fallback на палитру прототипа |
| Закрытие | `close()` после «Вступить» |

В `MAX_API_notes.md` вызовы записаны как `MaxApp.init()`; в кейсе упомянуты **MAX Bridge** и **MAX UI**. **[СВЕРИТЬ]** реальные названия объектов и методов, прежде чем писать обёртку. Обёртку сделать одним модулем (`maxBridge.ts`) с заглушками для запуска вне MAX.

## 11. Изменения к API-контракту (`14_env_and_api_contract.md`)

Контракт написан под старую механику. Что править:

**Исправить**

| Место | Проблема | Как должно быть |
|---|---|---|
| `GET /payments/{id}/status` → `invite_link` | отдаёт реальную ссылку MAX | `invite_url` = `{APP_BASE_URL}/i/{token}` |
| `GET /subscriptions/my` → `invite_link` | то же | убрать; ссылка выдаётся только через токен |
| Заголовок вебхука MAX | в контракте `X-Max-Bot-Secret`, в `MAX_API_notes` `X-Max-Bot-Api-Secret` | **[СВЕРИТЬ]** |
| Формат `bot_added` | расходится с notes | **[СВЕРИТЬ]** |

**Добавить (в контракте нет)**

| Эндпоинт | Зачем | Story |
|---|---|---|
| `GET /i/{token}` | редирект по одноразовому токену (не под `/api/v1`) | US-5.2 |
| `POST /api/v1/subscriptions/{id}/invite` | перевыпуск токена | US-5.3 |
| `GET /api/v1/business/plans` | список тарифов продавца с числом подписчиков | US-7.1 |
| `PATCH /api/v1/business/plans/{id}` | `is_active` вкл/выкл | US-2.3 |
| `DELETE /api/v1/business/plans/{id}` | только при 0 подписок и платежей, иначе 409 | US-2.3 |
| `GET /api/v1/business/export` | `.xlsx` | US-7.3 |
| `POST /api/v1/business/self-employed-confirm` | декларация (либо поле в `register`) | US-1.4 |

Дополнительно: `POST /api/v1/business/register` принимает `max_chat_id` от клиента, но привязка идёт по событию `bot_added`. Определить один источник истины (рекомендация — только `bot_added`, регистрация из мини-аппа без канала допустима).
