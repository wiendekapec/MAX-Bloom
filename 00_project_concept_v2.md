## 1. Проблема и пользователь

**Приоритетный пользователь:** самозанятый/ИП, который ведёт закрытое платное сообщество (канал/чат) в MAX — эксперт, тренер, автор курса, консультант.

**Формулировка проблемы:**
> Самозанятый, ведущий закрытый канал в MAX, хочет получать оплату за подписку автоматически, но сталкивается с тем, что должен вручную сверять переводы, помнить о сроках и кикать неплательщиков — из-за чего теряет выручку на забытых просрочках и рискует штрафом за невыставленный чек (ФЗ-54).

**Второстепенный пользователь (не герой питча, а часть сценария):** покупатель, который оформляет подписку на канал предпринимателя.

⚠️ Продукт **не** позиционируется как «маркетплейс/каталог контента для покупателей». Каталог — вспомогательный элемент внутри решения проблемы предпринимателя, а не самостоятельная ценность.

## 2. As-Is → To-Be

| | Сейчас (вручную) | С MAX Bloom |
|---|---|---|
| Приём оплаты | Реквизиты/QR в личке, ручная сверка | Оплата в 1 клик по СБП внутри MAX |
| Учёт подписчиков | Таблица/память | Автоматический журнал подписок в БД |
| Кик неплательщиков | Вручную, часто с опозданием | Шедулер кикает ежедневно автоматически |
| Чеки (ФЗ-54) | Часто не выставляются | Автоматически через ЮKassa ОФД |
| Двойные списания | Риск при повторной сверке | Защита через Idempotency-Key |

**Метрики эффекта (называть числом на защите):**
- время администрирования одного канала в месяц
- количество ручных действий предпринимателя на 1 продление
- доля вовремя оплаченных продлений (без потери подписчика)

## 3. Формат решения

**Чат-бот с подключённым мини-приложением.** Мини-апп не изолирован — открывается только из бота (deep link `?start=...`).

Два режима использования одного бота:
- **ЛК крейтора** — управление бизнесом (в боте + мини-аппе)
- **Поток покупателя** — выбор тарифа и оплата (в мини-аппе)

---

## 4. Сценарий 1 — Крейтор (приоритетный, это герой питча)

1. `/start business` → онбординг (самозанятость, ссылка на npd.nalog.ru)
2. Создание бизнес-профиля: название, описание, категория
3. Создание тарифа: название, цена, период
4. Привязка канала: добавить бота админом → событие `bot_added` → chat_id зафиксирован
5. Бот выдаёт **персональную deep-ссылку на тариф** с закодированным источником (`?start=plan_42_src_bot`, `?start=plan_42_src_story` и т.п.) — для трекинга конверсии
6. **Дашборд крейтора (мини-апп)** — главный по вниманию экран продукта:
   - выручка (за период)
   - число активных подписчиков
   - список последних платежей
   - конверсия по ссылкам (переходы → оплаты, по полю источника)
   - кнопка **«Экспорт в Excel»** → бэкенд отдаёт `.xlsx` (Apache POI)
7. Деактивация тарифа

---

## 5. Сценарий 2 — Покупатель (вспомогательный, минимальный по экранам)

1. Переход по deep-ссылке от крейтора **или** из ленты-заглушки
2. Карточка сообщества + тариф → кнопка «Оплатить через СБП»
3. Оплата (тестовый магазин ЮKassa, см. п.7) → webhook → подписка ACTIVE
4. Бот присылает одноразовую инвайт-ссылку в личку
5. **Ошибка оплаты** — отдельный обязательный экран: причина, кнопки «Попробовать снова» / «Написать в поддержку» (не мок, а рабочая ветка)
6. Уведомления: за 3 дня до истечения, в день истечения — с кнопкой «Продлить»

## 6. MoSCoW

## 7. Оплата — решение по вопросам

Используем **тестовый магазин ЮKassa (sandbox)**:
- Регистрируется бесплатно, без ИП/самозанятости команды
- Полный реальный цикл: `POST /v3/payments` → тестовая страница подтверждения → настоящий webhook `payment.succeeded`
- Вся логика (idempotency, статус, генерация инвайта) работает как в проде
- Разрешено правилами хакатона (FAQ п.13, 15) при явном указании в материалах

**Обязательно указать в README и на первом (служебном) слайде презентации:**
> Интеграция с ЮKassa используется в тестовом режиме (sandbox). Реальные списания не происходят.

## 8. Технические ограничения платформы MAX (зафиксировано, не обсуждается)

- Бот **не может** добавлять пользователей в чат — только инвайт-ссылки (`POST /chats/{chatId}/links`, `join_limit`)
- `POST /chats/{chatId}/members` удалён с 30.09.2026 — не использовать
- Кик — только `DELETE /chats/{chatId}/members`
- Только webhook в проде, long polling — не для сдачи
- Мини-апп подключается **только** через бота, не как отдельный сервис
- Ник/лого выданного бота менять нельзя на онлайн-этапе
- Работает и в мобильной, и в веб-версии MAX
